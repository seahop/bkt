Access bkt at:
  {{- range .Values.ingress.hosts }}
  https://{{ .host }}
  {{- end }}
{{- else }}

To access bkt locally, run:

  # Console — web UI + REST API (the UI is embedded in the backend)
  kubectl port-forward svc/{{ include "bkt.fullname" . }}-backend 9443:{{ .Values.backend.service.port }}

  # S3-compatible API (aws-cli / s3fs)
  kubectl port-forward svc/{{ include "bkt.fullname" . }}-backend 9000:{{ .Values.backend.service.s3Port }}

Then open https://localhost:9443 in your browser.
{{- end }}

S3 Compatibility:
  Endpoint: https://<s3-host>:9000
  Use your bkt access keys from the Settings page.

  aws configure --profile bkt
  aws s3 ls --endpoint-url https://<s3-host>:9000 --profile bkt

{{- if and (eq (.Values.backend.env.STORAGE_BACKEND | default "local") "local") }}

Storage note: STORAGE_BACKEND=local keeps object bytes on the backend PVC —
keep replicaCount at 1 (or use an RWX storage class). For stateless scale-out,
switch to STORAGE_BACKEND=s3.
{{- end }}
{{- if and .Values.ingress.enabled (not .Values.ingress.s3.enabled) }}

S3 API note: only the console is behind the ingress. Enable ingress.s3 (own
hostname) or expose the s3 service port via LoadBalancer for aws-cli/SDK
access, and set backend.env.S3_PUBLIC_ENDPOINT so presigned URLs work.
{{- end }}

{{- if and .Values.ingress.enabled (not .Values.backend.env.TRUSTED_PROXIES) }}

Rate limiting behind the ingress: TRUSTED_PROXIES defaulted to the private
ranges ({{ include "bkt.trustedProxies" . }})
so each user gets their own per-IP rate-limit bucket. Narrow it to your
ingress controller's pod CIDR via backend.env.TRUSTED_PROXIES — any client
inside a trusted range can spoof X-Forwarded-For.
{{- end }}
{{- if and (not .Values.ingress.enabled) (not .Values.backend.env.TRUSTED_PROXIES) }}

Rate limiting: TRUSTED_PROXIES is empty. If you put a proxy/LB in front of
the console, set backend.env.TRUSTED_PROXIES to its address/CIDR — otherwise
all users share the proxy's rate-limit bucket.
{{- end }}
{{- if .Values.postgresql.enabled }}

Database: the in-chart PostgreSQL connection is unencrypted (sslmode=disable,
cluster-internal). Restrict it with a NetworkPolicy, or use an external
database with externalDatabase.sslMode=verify-full.
{{- end }}
